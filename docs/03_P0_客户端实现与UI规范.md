# P0 客户端实现与 UI 规范｜H5 原型

> 文档状态：**生效**
> 最后更新：2026 年 9 月 8 日
> 适用范围：当前本地 H5 Canvas 原型；不是 Cocos 正式工程说明。

## 1. 当前运行结构

| 文件 | 职责 |
|---|---|
| `index.html` | 首页、法宝、灵宠、战斗、结算页面的结构与文案。 |
| `p0.css` | 竖屏布局、国风修仙配色、卡片、按钮、战斗信息层样式。 |
| `p0.js` | 本地存档、导航、战斗循环、波次、掉落、抓捕、结算、飞剑祭炼。 |
| `server/start_server.js` | 本地静态文件服务，提供 `http://127.0.0.1:3000/`。 |

## 2. 页面范围

### 2.1 荒原入口

- 展示万剑真君、仙石、第一章「幽冥荒原」入口。
- 唯一主操作为「踏入荒原」。
- 文案必须强调：守住护宗大阵、完成当前普通试炼。

### 2.2 法宝仙匣

- 展示青霄飞剑当前等级、伤害、攻击间隔、飞剑数量与吸附范围。
- 仅提供「祭炼飞剑」一个成长操作。
- 宝库只展示当前已获得的法器；不得增加一键装备、分解、套装、抽取等 P1 功能。

### 2.3 万灵御兽录

- P0 仅展示「寻木青雀」是否已缔结。
- 不提供灵宠编队、出战、升星、技能或属性加成。

### 2.4 战斗界面

- 顶部：暂停、关卡名、当前波次；Boss 出现时展示 Boss 血条。
- 中部 Canvas：上方妖物压境，下方为万剑真君和护宗大阵；万剑真君可在下半区域拖动移动，也支持方向键 / WASD。
- 底部：护宗大阵 HP、本局仙石、自动御剑和自动拾取说明。
- Boss 虚弱时：弹出两种抓捕选择；失败后清晰提示狂暴与额外掉落。

### 2.5 结算界面

- 必须表达：结局、阵线剩余、总伤害、Boss 结局和本次奖励。
- 返回操作只能回到荒原入口，形成下一局闭环。

## 3. UI 视觉约束

### 必须保留

- 竖屏单手浏览结构。
- Q 版国风、厚描边、青灰荒原、羊皮或青玉卡片、暖金色主按钮。
- 修仙御兽元素：飞剑、护宗阵线、妖物、青雀、法器、洞府。
- 清楚的战斗信息优先级：阵线 HP > Boss 血量 > 波次 > 本局仙石。

### 禁止出现

- 西幻国王、骑士、城堡、炮台、弓箭手等模板主题元素。
- 六角色战位、多人阵容、第二章、史诗/深渊副本入口。
- 商城、首充、礼包、广告、公会和排行榜入口。
- 仅为“看起来内容多”而添加、但无法服务本 P0 闭环的按钮。

## 4. 交互约束

1. 页面上所有主按钮必须使用真实 `button`，并绑定明确动作。
2. 页面切换、开始战斗、暂停、抓捕、祭炼、返回入口必须可点击。
3. 抓捕面板出现时战斗暂停；选择完成后：成功结算，失败继续战斗。
4. 浏览器刷新后应恢复仙石、飞剑等级、法器和灵宠等本地进度。
5. 修改按钮、`data-action` 或页面 `id` 时，必须完整试玩一局，防止再次发生“点击无反应”。

## 5. 本地存档

- 存档键：`wanjian_fengyao_p0_v3`。
- 保存内容：仙石、镇妖葫芦数量、飞剑等级、飞剑伤害、已获得法器、寻木青雀、通关标记。
- 清档方式：在浏览器站点数据中清除本地存储，或在开发工具执行 `localStorage.removeItem('wanjian_fengyao_p0_v3')`。
- 不得在当前 P0 中把 localStorage 与 MySQL 同时作为实时真源。

## 6. 改动限制

客户端成员在 P0 阶段可修改根目录 H5 文件以优化手感、信息表达和主题一致性；任何改变玩法范围的需求必须先更新 `01_P0_产品与开发基线.md`。
