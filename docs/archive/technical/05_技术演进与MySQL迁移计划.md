# 技术演进与 MySQL 迁移计划

> 文档状态：**规划，不作为当前 P0 开发任务**
> 最后更新：2026 年 9 月 8 日

## 1. 当前结论

当前项目只保留 H5 Canvas 可玩原型和本地静态试玩服务。早期 Cocos 骨架、NestJS 骨架、旧 MySQL 表结构、旧数值配置和旧测试脚本已全部清理，避免它们继续误导 P0 开发。

当前本地进度使用浏览器 `localStorage` 保存。P0 玩法和 QA 未稳定前，**不新建服务端工程、不接入数据库、不做账号系统，也不启动抖音小游戏部署。**

## 2. 启动迁移的前置条件

以下条件全部满足后，才允许创建新的 MySQL / 服务端开发分支：

1. `04_P0_QA验收与回归清单.md` 的关键路径稳定通过。
2. 飞剑、怪物、Boss、抓捕、掉落、结算数值已冻结一个测试版本。
3. 开发总控确认当前 P0 不再进行大范围玩法重做。
4. 明确账号体系、跨设备存档需求及测试环境。
5. 基于最终 P0 规则重新输出数据字段与接口清单。

## 3. 未来最小迁移数据

| 数据 | 当前来源 | 用途 |
|---|---|---|
| 玩家 ID / 昵称 | 新增 | 账号与存档归属。 |
| 仙石 | `gold` | 飞剑祭炼。 |
| 镇妖葫芦数量 | `gourds` | 抓捕库存。 |
| 飞剑等级 / 伤害 | `weaponLevel` / `weaponDamage` | 局外成长。 |
| 已获法器 | `equipment` | 收获展示。 |
| 寻木青雀状态 | `pet` | P0 唯一灵宠。 |
| 通关标记 | `cleared` | 副本完成展示。 |

当前不迁移：体力、门票、史诗/深渊、炼狱晶核、副本排行、多人、公会、商城和付费字段。

## 4. 未来服务端最小职责

1. 玩家存档读取与保存。
2. 单局结算奖励写入。
3. 镇妖葫芦库存校验及抓捕结果记录。
4. 基础请求校验与异常保护。

P0 后续服务端也不默认采用实时战斗同步；是否增加防作弊或实时能力，应在正式平台版本评审时另行确认。

## 5. 抖音小游戏适配顺序

H5 试玩稳定 → 确认正式客户端技术方案 → 适配平台生命周期与存档 → 真机性能测试 → 小范围测试。

当前状态：**目标平台为抖音小游戏，但尚未启动适配和部署。**
